# The Abundance film

A 72-second animation of the one thing this repo does: divide what the world
produces by how many of us there are, then look at where the result actually
goes.

**Every figure on screen is computed from [`data/essentials.json`](../../data/essentials.json)
at build time.** Nothing is typed into the film by hand. If the dataset is
corrected, the film's numbers change with it — that is the point of the last act.

## What it says

| Act | Beat |
|---|---|
| 1 | One light. It becomes 8,200,000,000 — the divisor. |
| 2 | Three resources divided by that number, each against its published minimum need: food **1.43×**, fresh water **287×**, electricity **3.93×**. |
| 3 | The light does not spread. 645M in hunger, 655M without electricity, 318M without housing, 847M in extreme poverty. *Scarcity is a shape, not a quantity.* |
| 4 | Every number has a vintage. 36 cited facts, 36 with a primary source, 46 commits keeping them current. |
| 5 | The arithmetic says it is possible. It does not say it is easy. |

### The one comparison the film refuses to make

`methodology.md:85` and the note on `extreme_poverty_line_usd_per_day` are
explicit: current US dollars and 2021 PPP international dollars are not
comparable, and nominal GDP must not be divided by the poverty line. So the film
computes ratios **only** for the three resources whose numerator and denominator
share a unit. Money appears in act 3 as a statement of position
(`$517.69T` household wealth, `$250.59T` of it above the $1m line), never as a
ratio. `facts.py` enforces this by construction — there is no code path that
produces a money ratio.

## Pipeline

Four passes. Each is independently re-runnable, and the split means the writing
can be re-cut without re-rendering a single frame.

```
facts.py      data/essentials.json  ->  film_facts.json     (the arithmetic)
scene.py      Blender/EEVEE Next    ->  render/f_%05d.png   (the 3D)
type_pass.py  PIL over those frames ->  comp/c_%05d.png     (the typography)
encode.py     Blender VSE + FFmpeg  ->  abundance.mp4       (H.264 + AAC)
```

Run the whole thing:

```sh
py build.py                      # all four passes, resumable
py build.py --spot 40,575,1330   # a few frames, for judging the look
```

### Notes that cost time to learn

- **The Microsoft Store Blender cannot be used.** `blender.exe` under
  `WindowsApps` returns *Permission denied* to any headless invocation. This
  uses a portable build (`~/blender/blender-4.2.9-windows-x64`).
- **`ffmpeg` on PATH here is a broken shim** — it exits 1 and writes zero bytes,
  and `ffmpeg ... | head` hides that because the pipe reports `head`'s exit code.
  Encoding goes through Blender's bundled FFmpeg. A real ffmpeg *is* available
  for probing (`imageio_ffmpeg`'s bundled binary; `broketobuilt/scripts/ffmpeg-path.mjs`
  resolves it) — that is how the shipped file's loudness was verified.
- **The encode pass must use the `Standard` view transform.** The composited
  PNGs are already display-referred; leaving it on AgX applies the tone map a
  second time and washes the film out.
- Per-point brightness reaches the shader as an `INSTANCER` attribute named
  `glow`, written per frame with `foreach_set`. `scene.py --probe` renders a
  half-lit field to prove that path still works before trusting a long render.
- Instance *scale* is driven by brightness too. Without that, unlit points are
  still opaque geometry and read as black blobs at close range.
- **Type is sized for a half-screen window (~780px), not a 1920px frame.** At
  that width the frame renders at ~40%, so a 16px citation is 6px on screen.
  `type_pass.py` carries a named scale with a 30px floor; every size derives
  from it. The scrim behind the column is 2D for the same reason — a horizontal
  gradient cannot protect text that sits low in frame over the lit field.

## Score

`score.wav` is generated by `broketobuilt/scripts/commercial/score-v3.mjs` —
original synthesis, no third-party recordings or samples, with swells landing on
the act boundaries in `marks.json`. Then `master_audio.py` lifts it: score-v3
normalises to −3.6 dBFS peak to leave headroom for a voiceover, and this film
has no voice, so that headroom is just quiet. It binary-searches the drive to
hit a measured RMS target through a soft saturator, and refuses to write if the
peak runs hot or if the 2-second window spread collapses — the section swells
are the point of that bed.

```sh
node ../../../broketobuilt/scripts/commercial/score-v3.mjs score.wav 72 marks.json
py master_audio.py score.wav score-master.wav --rms -14.5
```

`encode.py` prefers `score-master.wav` when it exists.

## Verifying the output

`verify_container.py abundance.mp4` parses the MP4 box tree and reports the
track count, handler types and duration — a check on the file itself rather than
on the encoder's own log line.
