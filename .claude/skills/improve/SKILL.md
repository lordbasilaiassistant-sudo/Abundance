# Ship one improvement

Read [`AGENTS.md`](../../../AGENTS.md) first (repo map, invariants, recipes),
then [`BACKLOG.md`](../../../BACKLOG.md) at the repo root.

The rule that makes this loop work: **one improvement per pass.** A pass that
ships one reviewable change every day compounds. A pass that ships five
half-finished ones gets the whole loop switched off.

## Choose

Take the **top item in "Next up" that you can finish and verify in this pass.**

- Sized `L` → do not build it. Write the proposal — options, trade-offs, your
  recommendation, what you need decided — and put it to the maintainer. That
  *is* the pass; it is done.
- Top item blocked (needs data not yet published, a decision, an external
  outage) → say so plainly, take the next one, and note why you skipped.
- Backlog empty of anything ready → do not invent scope. Say the backlog is
  clear, append any candidates you noticed, and stop. A quiet day is fine.

## Build

Inside the item's scope and no wider. The invariants in `AGENTS.md` are not
negotiable — in particular:

- **Never change a number, a source, or a claim as part of an improvement.**
  Data changes are their own PR, with the primary document read and cited. An
  improvement that quietly edits a figure is the one failure this repo cannot
  absorb.
- No framework, no build step, no package manager, no third-party runtime JS.
  The site stays editable in the GitHub web UI.
- No published path moves, renames, or disappears.
- Generated files are regenerated by their script, never hand-edited.
- Tone is arithmetic, not advocacy. Don't rewrite prose for style.

If the work turns out bigger than the sizing said, ship the coherent part that
stands on its own and leave the rest as a backlog item with what you learned.
Don't leave the repo half-converted.

## Verify

```bash
python3 scripts/check.py          # must pass before you push
python3 -m http.server 8000       # look at any page you touched
```

If your change adds an invariant anyone could break later, add a check for it
in `scripts/check.py` in the same PR, and negative-test it: break the thing
deliberately, confirm the check fails, restore, confirm it passes. An invariant
nothing enforces is a comment.

## Land

1. Branch, commit with a message saying *why*, not just what.
2. Open a **draft** PR. Body: what changed, how you verified it, the
   `scripts/check.py` output, and anything you deliberately left undone.
3. Update `BACKLOG.md` in the same PR — move the item to Done with the PR
   number, and append candidate ideas you noticed while working. The backlog is
   how the next pass knows where you stopped; leaving it stale breaks the loop.
4. Never merge, approve, or force-push. The maintainer decides what ships.
